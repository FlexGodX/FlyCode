# FlyCode

[English](README.en.md) · **Русский**

FlyCode — экспериментальный автономный агент для исправления кода. Он читает
файлы проекта, предлагает небольшие изменения, выбирает действие через
контроллер, вдохновлённый вычислительными механизмами мозга дрозофилы, и
проверяет результат тестами и состоянием приложения.

**Статус: рабочий MVP до фазы 4 включительно.** Агент самостоятельно исправляет
учебный FastAPI/PostgreSQL-проект, запускает Docker Compose, применяет миграции
Alembic и проверяет API. Доступны реальный граф FlyWire, его сокращённая версия
и офлайн-процедуры обучения; исследовательские критерии описаны ниже.

## Что умеет MVP

- Читать, искать, создавать и редактировать файлы, смотреть Git status/diff.
- Запускать тесты и выполнять ограниченный набор Docker/Postgres/Alembic/HTTP-инструментов.
- Выбирать действия с помощью Functional Fly или базовых контроллеров.
- Учитывать рабочую и эпизодическую память, новизну, повторение действий и результат выполнения.
- Блокировать известные опасные действия через safety mask.
- Завершать задачу только после необходимых проверок. Правки и перезапуск
  стека сбрасывают предыдущие подтверждения готовности.

По умолчанию используется **детерминированный эвристический генератор**: ему
не нужен API-ключ, но он решает только поддерживаемые учебные случаи. Для
семантического разбора других проектов можно подключить LLM.

## Установка

Проверенная версия Python — **3.12**. Для простого примера Docker не нужен.
Для демонстрации с сервисами требуются работающий Docker Engine и Docker Compose.

```bash
git clone https://github.com/FlexGodX/FlyCode.git
cd FlyCode
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
flycode brains
```

В PowerShell окружение активируется командой `.venv\Scripts\Activate.ps1`.

## Интерфейс агента

```bash
flycode ui --workspace . --port 8790
```

Откройте **http://127.0.0.1:8790**. Нужен только установленный FlyCode: Node.js,
сборка интерфейса и внешний сервер не требуются.

- **«Попробовать на демо»** запускает реальное исправление учебной ошибки без моделей.
- Для своей задачи выберите проект, опишите результат и нажмите стрелку или
  `⌘ Enter` / `Ctrl Enter`. По умолчанию используются локальные Qwen + Jev.
- В диалоге видны обоснования выбранных действий, вызовы моделей, инструменты и
  результаты проверок. Раскройте «Почему это действие», чтобы сравнить кандидатов
  и оценки Jev; вкладка «Изменения» показывает успешно применённые правки.
- Панель справа подсвечивает текущий этап и показывает режим, уверенность
  контроллера, риск, шаги и число реальных вызовов моделей. На узком экране она
  открывается кнопкой в правом верхнем углу.
- Настройки моделей и лимит шагов доступны по кнопке рядом с полем задачи.
  «Остановить» дожидается текущего вызова; новые действия после остановки
  не запускаются. Уже применённые правки сохраняются.

`--workspace` ограничивает выбор проектов этой папкой. Для нескольких проектов
укажите их общий каталог. **Агент изменяет файлы выбранного проекта напрямую**;
демонстрация всегда создаёт отдельную папку и не пересоздаёт ваш проект.
Одновременно выполняется одна задача. Интерфейс доступен только на локальном
компьютере и не публикуется в интернет.

История и события хранятся в `~/.local/share/flycode/ui`; `--data-dir PATH`
позволяет выбрать другое место. Для демо файлы находятся в
`<data-dir>/<run-id>/repository`. Обновление страницы восстанавливает журнал;
после перезапуска сервера незавершённые задачи помечаются прерванными.
Обоснования — это краткие объяснения действий, не скрытая цепочка мыслей модели.
Схема показывает выбранный контроллер и вызовы компонентов; для `full` доступны сведения о реальном графе.
Большие результаты инструментов в интерфейсе сокращаются до 16 000 символов.

## Первый запуск без API-ключа

```bash
flycode run \
  --repo /tmp/flycode-toy \
  --fixture toy_arithmetic_bug \
  --task "Fix the bug" \
  --brain functional \
  --control bias
```

Агент создаст учебный проект с ошибкой, исправит его и запустит тесты. При успехе
вывод содержит `success=True`, а процесс завершается с кодом `0`.
Для примера с отсутствующим импортом используйте `--fixture toy_import_bug`.

**Каталог, переданный вместе с `--fixture`, пересоздаётся. Используйте отдельный
временный каталог, а не существующий проект.** В Windows замените `/tmp/...`
на путь к своему временному каталогу.

## Демонстрация: исправить и запустить FastAPI + PostgreSQL

Убедитесь, что Docker работает и порт **8000** свободен. PostgreSQL доступен
внутри сети Compose; свободный порт 5432 на хосте не требуется. При первом
запуске нужен интернет для загрузки образов и зависимостей.

```bash
docker info
docker compose version

flycode run \
  --repo /tmp/flycode-environment \
  --fixture fastapi_postgres_app \
  --task "Fix this FastAPI application and get it fully running" \
  --brain functional \
  --control bias \
  --max-steps 60 \
  --max-tool-calls 60

curl --fail http://localhost:8000/health
curl --fail http://localhost:8000/users
```

В примере намеренно сломаны конфигурация порта, путь миграций, обращение к
переменной окружения, маршрут API и Python-импорт. Агент выводит исправления из
прочитанных файлов и результатов инструментов. Затем он собирает контейнеры,
проверяет PostgreSQL, выполняет миграцию и тесты внутри контейнера приложения
и проверяет `/health` и `/users` по HTTP.

Приложение продолжает работать после завершения агента. Чтобы остановить его:

```bash
docker compose --project-directory /tmp/flycode-environment down
```

## Настоящий коннектом FlyWire — фаза 5

```bash
python -m pip install -e '.[research]'
flycode connectome download
flycode connectome prepare --source ~/.cache/flycode/flywire-783
flycode connectome info
flycode run --repo /tmp/flycode-full --fixture toy_arithmetic_bug \
  --task "Fix the bug" --brain full
```

Первая загрузка получает два официальных файла, около 853 МБ, и проверяет
контрольные суммы. Источник: [FlyWire Consortium, v783, CC BY 4.0](https://zenodo.org/records/10676866).
Данные остаются в локальном кеше и не входят в репозиторий.

Подготовленный граф содержит все **139 255** опубликованных нейронов и
**2 700 513** направленных связей после объединения областей и порога
в 5 синапсов. `--connectome-path PATH` или `FLYCODE_CONNECTOME_PATH`
позволяет выбрать подготовленный граф. При отсутствии данных случайной
подмены не происходит: запуск завершается с ошибкой.

В интерфейсе выберите «Нейронный контроллер → FlyWire 783» в настройках.
К нему подключаются те же Qwen и Jev; нейронное состояние участвует в
маршрутизации вызовов и оценке действий. В плане название Hermes обозначает
сам FlyCode — приложение, в котором работают эти агенты.

Это исследовательская модель: реальная топология работает с приближённой
рекуррентной динамикой, программно заданными входами/выходами и начальным
приоритетом этапов работы. Знаки связей оцениваются по нейромедиаторам;
GABA/GLUT считаются тормозящими, остальные — возбуждающими. Это допущение,
не полная биофизическая симуляция. Старый `frozen_connectome` сохранён как
эксперимент со случайной проекцией. Преимущество перед Functional Fly ещё
не доказано; измерения обучения и уменьшения графа приведены ниже.

## Офлайн-обучение, сокращение графа и перенос поведения

Сначала запишите успешные запуски. В обучение попадают **все** действия из
выбранной папки: перед использованием проверьте траектории. Новые эпизоды
распознаются по файлам и сбросу номера шага; состояния между ними не смешиваются.

```bash
flycode run --repo /tmp/flycode-teacher-add --fixture toy_arithmetic_bug \
  --task "Fix the bug" --brain functional --telemetry-dir ~/.cache/flycode/training-records
flycode run --repo /tmp/flycode-teacher-import --fixture toy_import_bug \
  --task "Fix the bug" --brain functional --telemetry-dir ~/.cache/flycode/training-records

flycode train --trajectories ~/.cache/flycode/training-records \
  --output ~/.cache/flycode/checkpoints/constrained
flycode run --repo /tmp/flycode-trained --fixture toy_arithmetic_bug \
  --task "Fix the bug" --brain full --checkpoint ~/.cache/flycode/checkpoints/constrained

flycode connectome reduce --source ~/.cache/flycode/flywire-783/prepared \
  --neurons 4096 --output ~/.cache/flycode/reduced-4096
flycode run --repo /tmp/flycode-reduced --fixture toy_arithmetic_bug \
  --task "Fix the bug" --brain reduced --connectome-path ~/.cache/flycode/reduced-4096

flycode distill --trajectories ~/.cache/flycode/training-records \
  --teacher-checkpoint ~/.cache/flycode/checkpoints/constrained \
  --output ~/.cache/flycode/checkpoints/student
# Только после успешной проверки distill:
flycode run --repo /tmp/flycode-student --fixture toy_arithmetic_bug \
  --task "Fix the bug" --brain functional --checkpoint ~/.cache/flycode/checkpoints/student
```

`train` подбирает усиление рекуррентных связей и скорость обновления состояния,
обучает выходные оценки инструментов. Матрица связей неизменна; входы, выходы,
параметры динамики и контрольные суммы сохраняются в отдельном checkpoint.
`training.json` содержит ошибки подражания и точность до/после обучения.
Это оценка на обучающих примерах, не доказательство улучшения решения задач.

`connectome reduce` выбирает связный участок существующего графа и наследует
соответствующие входы и выходы полной модели. Новые связи не создаются;
`--checkpoint PATH` позволяет использовать обученные параметры родителя.

`distill` переносит **оценки инструментов** в небольшой выходной слой Functional Fly;
выбор режима поведения остаётся прежним. Целые эпизоды выделяются для проверки.
По умолчанию нужны RMSE ≤ 0,1 и совпадение лучшего инструмента ≥ 90%; параметры
`--max-rmse` и `--min-agreement` задают допуск до эксперимента. При непрохождении
команда возвращает код 1 и сохраняет отчёт; такой checkpoint нельзя включить.
Эти исследовательские команды сейчас доступны через CLI.

Вторая версия студента использует 784 параметра и квадратичные признаки;
старые линейные checkpoint остаются совместимыми. Проверка воспроизводит
настоящий контроллер с его состоянием и историей действий.

Измерения на этом компьютере: два учебных проекта, seeds 0/1/2, `bias` и `hard`.
[Сводный отчёт](docs/research-results/2026-10-15-adaptation.json) сохраняет условия и результаты.

| Проверка | Результат |
|---|---|
| Фаза 6, обычный генератор | Исходная и обученная версии: 12/12, по 5 шагов |
| Фаза 6, эксперимент с альтернативными действиями | Исходная: 10/12, в среднем 6,67 шага; обученная: 12/12, 5 шагов |
| Граф из 4 096 нейронов, 12 031 связи | 4/4 успешных ремонта, по 5 шагов |
| Шаг полного / сокращённого графа | 7,11 / 0,12 мс; массивы 30,17 / 0,38 МиБ |
| Фаза 8, перенос в Functional Fly | Отложенный эпизод: RMSE 0,01679, совпадение 100%; порог пройден |
| Студент на реальных запусках учебных задач | 12/12; исходный Functional Fly также 12/12, по 9 шагов |

Фазы 6–8 прошли ограниченную приёмку на этих данных. В эксперименте фазы 6
генератор сохраняет обычные предложения и добавляет диагностические `run_tests`
и `git_diff` в режиме EXECUTE. Разница получена при seed 0 в `hard`; при других
seeds преимущество не обнаружено. Каждый checkpoint сравнивался со своей
исходной инициализацией. Порог фазы 8 проверен на одном отложенном эпизоде.
Эти замеры не доказывают обобщение на новые проекты или преимущество над
FSM/RNN при одинаковых вычислительных затратах.

## Сохранение опыта и исследовательские проверки

Фаза 10: Functional Fly учится только на результатах выполненных действий.
Память сохраняется между задачами; обновления MB/RPE, размер памяти и изменение
политики ограничены. Проверка на сохранённых примерах отклоняет ухудшающие
обновления и восстанавливает снимок политики. По умолчанию обучение выключено.

```bash
flycode run --repo /tmp/flycode-learn-add --fixture toy_arithmetic_bug \
  --task "Fix the bug" --learning-memory ~/.cache/flycode/experience
flycode run --repo /tmp/flycode-learn-import --fixture toy_import_bug \
  --task "Fix the bug" --learning-memory ~/.cache/flycode/experience

flycode benchmark --config docs/examples/benchmark.json \
  --output ~/.cache/flycode/benchmarks
flycode lesion --trajectories ~/.cache/flycode/training-records \
  --checkpoint ~/.cache/flycode/checkpoints/constrained --fraction 0.1 \
  --output ~/.cache/flycode/lesion.json
flycode sensitivity --trajectories ~/.cache/flycode/training-records \
  --checkpoint ~/.cache/flycode/checkpoints/constrained \
  --parameter recurrent_gain --values 0.6 0.9 1.2 \
  --output ~/.cache/flycode/sensitivity.json
```

Для обучения без сохранения на диск используйте `--learn`. Сохраняйте прежний
`--seed` при загрузке опыта: файл связан с проекцией признаков. Счётчики проверки
обновлений относятся к текущему экземпляру контроллера; число обучений MB
сохраняется. В серии из 36 запусков обучение и замороженный контроллер решили
все задачи за 9 шагов: ускорение адаптации ещё не подтверждено.

`benchmark` создаёт отдельные проекты и журналы для каждого варианта. Пока
поддерживаются два учебных проекта, указанных в примере. Поле `cortex` принимает
`heuristic` или исследовательский `tournament`. Для сравнения обученной и исходной
модели задайте отдельную конфигурацию на каждый seed и соответствующий checkpoint.
Отчёт показывает фактические затраты; их равенство не предполагается.

Фаза 11 реализована частично: отключение входов/связей выбранных нейронов и
чувствительность параметров измеряются на записанных траекториях. Структура
графа сохраняется, исходные файлы не меняются. `counterfactual_task_success`
остаётся `null`: это не повторное решение задачи с повреждённой сетью.

## Теневой наблюдатель — фаза 12

```bash
flycode run --repo /tmp/flycode-shadow --fixture toy_arithmetic_bug \
  --task "Fix the bug" --brain functional --shadow-brain full \
  --telemetry-dir ~/.cache/flycode/shadow-records
```

Рабочий контроллер управляет агентом и вызовами моделей; наблюдатель оценивает
те же варианты с той же маской безопасности и **нулевым влиянием** на выбор.
Поля `shadow_decision` в `*.steps.jsonl` сохраняют оба выбора, совпадение,
разность ожидаемого риска и задержку. Альтернативный успех и число вызовов
не оцениваются. Ошибка наблюдателя записывается и не останавливает рабочего
агента. Доступны `--shadow-connectome-path` и `--shadow-checkpoint`.

На реальном FlyWire обе учебные задачи выполнены за 9 шагов; действия полностью
совпали с запуском без наблюдателя, рекомендации совпали в 12 из 18 случаев.
Пока это CLI-режим и начальная телеметрия. Для перехода к фазам 13–14 нужны
более широкие проверки и управляемое увеличение влияния контроллера.

## Локальные Qwen + Jev в LM Studio

FlyCode поддерживает две локальные модели с разными ролями:

- `qwen/qwen3.5-9b` формирует конкретные варианты действий.
- `jev-style-qwen3.5-2b-decision` оценивает безопасные варианты по вероятностям
  следующего токена в своём родном формате выбора.
- Fly-контроллер управляет вызовами моделей и сохраняет итоговый выбор действия.
  Можно выбрать Functional Fly или подготовленный реальный граф через `--brain full`.

Если модели уже скачаны, загрузите их в LM Studio и включите локальный сервер:

```bash
lms load qwen/qwen3.5-9b --context-length 8192 -y
lms load jev-style-qwen3.5-2b-decision --context-length 4096 -y
lms server start --port 1234

flycode run \
  --repo /tmp/flycode-local \
  --fixture toy_arithmetic_bug \
  --task "Fix the off-by-one bug in add and verify the tests" \
  --brain functional \
  --llm lmstudio \
  --base-url http://127.0.0.1:1234/v1 \
  --model qwen/qwen3.5-9b \
  --decision-model jev-style-qwen3.5-2b-decision \
  --request-timeout 120 \
  --max-model-calls 30 \
  --telemetry-dir /tmp/flycode-local-telemetry
```

Если сервер уже работает, повторно запускать его не нужно. Идентификаторы
моделей берутся из API LM Studio; при несовпадении программа покажет доступные
ID. Имена выше являются значениями по умолчанию для `--llm lmstudio`.
`LMSTUDIO_BASE_URL` задаёт адрес сервера, а `LMSTUDIO_API_KEY` — ключ, если
в LM Studio включена аутентификация. Облачный API автоматически не используется.

Контроллер пропускает модели при подтверждённом завершении, своей блокировке
или простой проверке тестов в режиме VERIFY. При уверенности не ниже 0.8 Jev
не вызывается. В `hard` итоговое ранжирование принадлежит контроллеру, поэтому
запрос Jev также пропускается. Safety mask проверяет действия независимо от
оценок моделей. При отказе Jev сохраняются предложения Qwen с диагностикой;
при отказе Qwen агент останавливается без выдуманного исправления. Запросы
ограничены тайм-аутом, числом токенов и общим бюджетом; автоматических повторов нет.

В выводе есть строки `[models]` и счётчики `model_calls`. В телеметрии
сохраняются маршрут вызовов, оценки Jev и ошибки. Сводка задачи не вызывает
дополнительный LLM-запрос. Приёмка с установленными моделями включается явно:

```bash
FLYCODE_TEST_LMSTUDIO=1 python -m pytest tests/e2e/test_lmstudio.py -q
```

## Работа с существующим проектом и LLM

Задайте `OPENAI_API_KEY` в окружении и запустите:

```bash
flycode run \
  --repo ./my-project \
  --task "Fix the failing tests" \
  --brain functional \
  --llm openai
```

Модель выбирается параметром `--model`; текущая модель по умолчанию —
`gpt-4o-mini`. Доступ и расходы зависят от выбранного API и модели.
Для существующего проекта не передавайте `--fixture`.

Агент изменяет файлы и может запускать инфраструктурные инструменты.
Используйте отдельную рабочую копию и среду разработки. Safety mask —
дополнительная проверка, а не изолирующая граница для недоверенного кода.

## Контроллеры и режимы

| Параметр `--brain` | Назначение |
|---|---|
| `functional` / `functional_fly` | Functional Fly: Task Compass, ассоциативная память, новизна и сигналы результата |
| `mock` | Контроллер для тестов |
| `heuristic_fsm` | Базовая конечная машина состояний |
| `random_reservoir` | Базовый случайный резервуар |
| `generic_rnn` | Базовая рекуррентная сеть |
| `reduced` | Сокращённый биологический граф с наследованием параметров родителя |
| `full` | Настоящая разреженная топология FlyWire с приближённой рекуррентной динамикой |
| `frozen_connectome` / `frozen_full_connectome` | Прежние экспериментальные случайные проекции |

`--control bias` — режим по умолчанию: fly-контроллер влияет на ранжирование
предложений. `--control hard` выбирает действие по оценке контроллера.
В обоих режимах действует safety mask.

## Как устроен цикл

```text
Наблюдение → контроллер → кандидаты действий → safety mask
          → выбор действия → инструмент → новое наблюдение
          → проверка результата → завершение
```

Дорогой семантический разбор выполняет LLM либо ограниченный эвристический
генератор. Лёгкий контроллер хранит состояние стратегии и влияет на выбор
действий. Тесты, сервисы и миграции дают проверяемую обратную связь.

## Проверки

```bash
python -m pytest -q
python -m pytest tests/e2e/test_environment_autonomy.py -q
FLYCODE_TEST_CONNECTOME=1 python -m pytest tests/e2e/test_real_connectome.py -q
```

Актуальный результат общего прогона указан в [статусе проекта](docs/handoff.md);
приёмка LM Studio и реального графа включается отдельно.
Приёмочные Docker-тесты действительно запускают агента с Docker/Postgres в режимах `bias` и
`hard`, проверяют HTTP и ревизию Alembic в базе. Они выбирают свободный
HTTP-порт и удаляют свои контейнеры после завершения. Без Docker/Compose
эти два теста явно пропускаются.

Проверки Ruff/mypy для всего проекта пока не проходят: остаются замечания
по стилю и типам. Подробности — в [статусе проекта](docs/handoff.md).

## Ограничения и дальнейший план

- Эвристический генератор не является универсальным исправителем кода.
- Преимущество fly-контроллера над сопоставимыми FSM/RNN пока не доказано.
- Приёмка фаз 6–8 ограничена учебными задачами; обобщение ещё не проверено.
- Фаза 10: механизм обучения готов, ускорение адаптации на задачах не доказано.
- Фаза 11: нужны другие коннектомы, сопоставимые вычислительные бюджеты и новые проекты.
- Фаза 12: нужен более широкий сбор телеметрии; фазы 13–14 ещё не реализованы.
- Исследовательские режимы доступны через CLI; в UI пока Functional Fly и замороженный FlyWire.
