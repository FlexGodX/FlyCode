# Durable parent continuation — checked checkpoint,2026-10-19

Version4 `Pipelines.approve_parent` grants a bounded preparation attempt for an
executable root, then releases its exact stopped process/slot while mandatory
children execute and complete independent reviews. A durable typed checkpoint
pins partial bytes and bounded previous-run context. A new fenced root attempt
composes exact child proofs and restores compatible partial changes; it retains
all earlier spending, the original deadline and attempt limits. Parent success
still requires its own independent criteria and merged/applied integration.

The real five-task route uses six attempts,3 loopback HTTP model calls and36
tool calls, with zero reservations or unknown outcomes. Parent lifetime2/2
splits1/1 preparation and1/1 continuation. Owner dirty/untracked bytes survive.
Identical deletions by parent/child are compatible. Partial work never issues a
completion receipt. Lost checkpoint bytes invalidate the completed workflow.
