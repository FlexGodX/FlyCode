Task2 of the dependent-execution plan composes checked predecessor outputs into
an isolated checkout. Admission pins exact receipt IDs/hashes; workspace and
artifact records retain that lineage and an input snapshot, separately from the
original owner source. Missing, foreign, revoked or changed prerequisites block
admission/publication. No source/evidence filesystem inspection runs inside SQL.

Final integration validates the selected ancestry and derives one original-to-final
delta. Sequential A:0→1, B:1→2 becomes2; independent incompatible edits remain
conflicts. Branch joins and identical deletions work without double application.
Every original criterion is checked against both the combined and applied result.
The final acceptance baseline remains the original source, regardless of artifact
ordering or repeated revalidation. Registered verification imports use the composite
input while retaining original provenance. Old manifests and proof hashes remain
readable without rewriting them.

The owned integrator preserves receipts while between file installations; this
pending state is never a successful verdict. A read-only Store can inspect a managed
Host's transition without acquiring runtime authority. Conflict repair reads both
exact versions, receives independent review and verifies all retained criteria.
Reopening requires fresh review/checks; historical receipts are audit provenance,
not authority to launch a dependent task. Both aggregate-root and completed-author
root layouts retain their review history. Root reopening invalidates the integrated
result before cascading receipt revocation, preserving exact restoration markers.
