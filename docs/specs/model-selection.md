# Выбор моделей и раздельные настройки выполнения

Статус: реализация начата по [плану поставки](../superpowers/plans/2026-10-16-specification-delivery.md).
Nullable scorer, каталог с явными probes и две панели реализованы. Live single-Qwen
repair ещё не принят: проверочный запрос завершился тайм-аутом. Версия требований: 1.0 · 16 октября 2026.
Основной план: [§102](../Plan.md#102-выбор-моделей-и-раздельные-настройки).

## 1. Пользовательский результат — MOD-01

Пользователь может запустить Qwen самостоятельно, без установленного или
доступного Jev, либо выбрать связку Qwen + Jev. Позже в тот же интерфейс
добавляются другие подключённые модели. Основная модель и необязательный
оценщик — разные роли; выбор одной модели не означает отключение коннектома.

В панели ввода есть две соседние независимые кнопки в таком порядке:

```text
[ Проект ]   [ Qwen 3.5 9B ▾ ] [ Параметры ⚙ ]                  [ Отправить ]
                       модели        справа от моделей
```

В режиме двух моделей первая кнопка показывает, например, «Qwen + Jev».
При выборе других моделей используются их реальные отображаемые имена.
Кнопка «Параметры» всегда расположена непосредственно справа от кнопки моделей
и открывает коннектом, шаги и остальные параметры выполнения.
Слово «одной кнопкой» означает одну общую точку выбора всех модельных ролей;
пользователь не должен искать основную модель и оценщик в разных настройках.

## 2. Модельные режимы — MOD-02

| Режим | Начальный вариант | Поведение |
|---|---|---|
| Одна модель | Только Qwen 3.5 9B | Основная модель предлагает действия; дополнительный оценщик отключён |
| Основная + оценщик | Qwen 3.5 9B + Jev 2B | Основная предлагает, оценщик по запросу контроллера оценивает безопасных кандидатов |
| Демо без моделей | Встроенные правила | Отдельный учебный режим, явно обозначенный как работа без LLM |

В single-режиме не создаётся клиент Jev, не проверяется его наличие и не
выполняются запросы/загрузка оценщика. Все используемые токены, счётчики,
события и обязательные зависимости относятся только к выбранной основной модели.
Отсутствие Jev не блокирует «Только Qwen». Нельзя заменить отключённого оценщика
скрытым вторым вызовом Qwen для той же роли.

Существующая логика контроллера сохраняется: возможны локальная проверка,
проверенное завершение без inference и вызов основной модели при необходимости.
Кандидаты проходят безопасность и существующее ранжирование с fly bias.
Отсутствие оценщика не даёт LLM прямого обхода контроллера, бюджетов или STOP gate.

В dual-режиме оценщик вызывается только когда это требуется маршрутизацией,
есть альтернативы после safety mask и остался общий бюджет. Сам факт выбора
двух моделей не обещает два запроса на каждом шаге. Недоступная модель при
подготовке даёт понятную ошибку и предложение выбрать доступный вариант;
переключение режима требует решения пользователя. Ошибка оценщика внутри
запуска сохраняется в trace вместе с фактическим использованием предложений
основной модели, а не выдаётся за успешную работу оценщика или новый single-run.

В демо не выполняются модельные запросы. Он остаётся доступен только там,
где разрешён текущим проектным режимом. Привязки неактивных моделей не
участвуют в эффективной идентичности демо, но могут храниться как пользовательский
выбор для возврата к локальным моделям.

## 3. Каталог будущих моделей — MOD-03

Набор моделей не зашивается в HTML как закрытый список «Qwen/Jev».
Серверный реестр объединяет зарегистрированные endpoints и результаты обнаружения
моделей. Первая поставка использует имеющийся LM Studio; другие модели того же
совместимого endpoint добавляются без новой ветки кода на каждое название.
Другой протокол требует отдельного адаптера провайдера и его проверки.

Предлагаемый `ModelDescriptor` содержит серверный `model_ref`, display_name,
provider/endpoint ref, фактический provider model ID, доступность, поддерживаемые
роли, проверенные capabilities, версию capability profile и источник сведений.
Checksum/revision весов хранится, если провайдер его сообщает; отсутствие
этой информации отмечается, а не заменяется предположением по model ID.
Секреты и произвольные URL не передаются браузеру в качестве параметров подключения.

Модель поддерживает одну или обе роли:

- Основная: принимает требуемый контекст и возвращает валидные структурированные
  предложения действий через выбранный адаптер.
- Оценщик: возвращает ограниченные finite scores для переданных candidate IDs
  по зафиксированной схеме. Наличие chat API само по себе не доказывает эту способность.

Состояния записи: `discovered`, `ready`, `unavailable`, `unsupported`.
Обнаружение в `/models` означает видимость на сервере, а не гарантию загрузки
в GPU или совместимости со схемой FlyCode. Неизвестные capabilities показываются
явно; профиль роли подтверждается зарегистрированной проверкой совместимости.
Пробный inference запускается только отдельным действием с показанным лимитом
и учётом расхода. Открытие меню и обновление списка не запускают модели.

Меню позволяет выбрать любую `ready`-модель для разрешённой роли, а для остальных
показывает причину недоступности. Фильтр по роли не зависит от семейства/бренда.
Нельзя автоматически подставлять Qwen вместо недоступной будущей модели.
Для текущего dual-контракта основная и оценщик имеют разные model IDs в одном
endpoint; работа двух разных endpoints — отдельная явно поддержанная возможность
адаптера, а не молчаливое изменение существующего LM Studio factory.

Регистрация модели и endpoint — отдельное серверное действие. При будущем
подключении облачного провайдера передача данных проекта разрешается явно
для этого назначения; выбор названия модели не расширяет доступ автоматически.

## 4. Одна кнопка выбора моделей — MOD-04

Нажатие кнопки моделей открывает одно компактное меню/панель со следующими полями:

1. Режим: «Одна модель», «Основная + оценщик», «Демо без моделей».
2. Основная модель: выбирается из каталога; начальный single-вариант — Qwen.
3. Оценщик: появляется только в dual-режиме; начальный вариант — Jev.
4. Краткий статус подключения и действие «Обновить список».

Верхние быстрые варианты «Только Qwen» и «Qwen + Jev» доступны, когда эти модели
подключены; это shortcuts к общему каталогу, а не единственные разрешённые модели.
После появления новых моделей пользователь выбирает их в тех же полях.
Меню содержит локальный поиск, если вариантов много, и показывает фактическое
имя/роль, а не технический путь к файлу весов.

Выбор готового варианта применяется к следующей задаче без второй общей кнопки
«Сохранить настройки». Несовместимая неполная пара не применяется: прежний валидный
выбор сохраняется, рядом указана причина. Escape/клик снаружи закрывают меню;
фокус возвращается на кнопку. Закрытие незавершённого выбора не создаёт полупары.
Настройки коннектома и бюджетов в этой панели не находятся и не изменяются.

Подпись кнопки: имя основной модели для single, краткие имена обеих для dual,
«Без моделей» для demo. Длинная подпись сокращается визуально, но полное имя
и режим доступны в tooltip/accessible name и открытом меню. Разработчик не
должен оставлять постоянный текст «Qwen + Jev» после выбора другой модели.

## 5. Отдельная кнопка параметров справа — MOD-05

«Параметры» содержит только настройки исполнения:

- Активный коннектом/контроллер и локальный артефакт.
- Наблюдатель, влияние, режим выбора действий и действующий допуск.
- Обучение, профиль памяти и seed.
- Максимум шагов, действий, суммарных вызовов моделей и timeout, когда он доступен.

Бюджет модельных запросов остаётся общим параметром выполнения, а не полем
выбора конкретной модели. Изменение этих настроек не меняет выбранные model IDs
и не включает Jev. Изменение single/dual не сбрасывает коннектом, шаги или память.
Если сочетание не соответствует допуску, показывается конкретная причина;
настройки не переписываются скрыто для получения подходящего допуска.

При активном запуске оба набора относятся к зафиксированному request snapshot.
В первой поставке обе кнопки заблокированы до окончания/остановки задачи,
как текущая кнопка настроек; события показывают реально используемые параметры.
Переключение модели посреди одной попытки не является частью этой поставки.

На desktop и mobile порядок одинаков: модели слева, параметры непосредственно
справа. Для узкого экрана текст параметров может стать иконкой шестерёнки с
accessible name «Параметры агента». Группа не меняет порядок и не разбивается
переносом между этими кнопками. При нехватке места сокращается подпись модели;
кнопки отправки/остановки остаются доступными без горизонтальной прокрутки.
Минимальная область нажатия каждой новой кнопки — 44 × 44 CSS px.

## 6. Контракты, совместимость и допуск — MOD-06

Режим имеет однозначную нормализованную конфигурацию. Предлагается сохранить
текущую структуру полей и разрешить `decision_model = null`:

| Режим | `llm` | `model` | `decision_model` |
|---|---|---|---|
| Только Qwen | `lmstudio` | `qwen/qwen3.5-9b` | `null` |
| Qwen + Jev | `lmstudio` | `qwen/qwen3.5-9b` | `jev-style-qwen3.5-2b-decision` |
| Другая основная модель | `lmstudio` | ID выбранной совместимой модели | `null` |
| Другая совместимая пара | `lmstudio` | ID основной | ID оценщика |
| Демо | `heuristic` | Неактивное поле | Неактивное поле |

Таблица задаёт контракт; API уже принимает явный `null`. Каталог выдаёт server refs
для probes, запрос запуска сохраняет совместимые фактические IDs и доверенный endpoint;
клиент не получает возможность передать произвольный URL. Режим выводится из
`llm` и наличия оценщика, а не из второго независимого флага, способного им противоречить.

Исторический request без новых настроек сохраняет прежний default Qwen + Jev.
Отсутствующее поле оценщика означает legacy default; явный `null` — отключение.
Пустая строка и строки «null»/«none» не являются корректным способом отключения.
Существующие CLI/config defaults не меняются скрыто. Отдельный CLI-параметр
отключения оценщика `--no-decision-model` сериализует тот же нормализованный контракт.

История восстанавливает модельный выбор и параметры выполнения независимо.
Недоступная историческая модель остаётся видимой с причиной и не заменяется
default при открытии старой задачи. Новый запуск требует доступной конфигурации.
Предпочтение следующего запуска и параметры просматриваемого выполненного запуска
различаются; открытие истории само по себе не меняет личный default.

Cortex factory, RunRequest, экспериментальный CortexConfig и cortex identity
должны одинаково понимать отключённого оценщика. В single-режиме factory проверяет
только основную модель и использует тот же контролируемый inference path,
а не отдельный путь, обходящий neural routing. В интерфейсе состояния оценщик
помечен «Отключён», счётчики не содержат выдуманных запросов Jev и события
`model_start/model_end` для него отсутствуют.

Допуск и experiment identity включают фактическую основную модель, наличие
оценщика, его идентичность при наличии и версию capability profile/маршрутизации.
Допуск Qwen + Jev не разрешает single-Qwen и наоборот; будущая модель или пара
требует своих измерений. Снижение числа моделей не считается автоматически
эквивалентным или безопасным изменением политики. Raw schema старых evidence
не изменяется задним числом, а несовместимость отображается явно.

В будущей команде агентов из §100 тот же каталог задаёт модельные привязки
профилей. Single-режим отключает Jev-оценщика, но сам по себе не уменьшает число
профилей/экземпляров Qwen и не меняет DAG команды. Выбор моделей одной кнопкой
не является кнопкой запуска отдельного агента.

## 7. Критерии приёмки — MOD-07

| ID | Проверяемое поведение |
|---|---|
| MS-01 | Только Qwen запускается при отсутствии Jev; Jev-клиент не создаётся, его availability/inference не запрашиваются |
| MS-02 | Single сохраняет neural routing, safety, бюджеты, локальные verify/STOP и не вызывает скрытый второй Qwen вместо Jev |
| MS-03 | Dual сохраняет условный вызов оценщика и учитывает обе модели в общем бюджете; ошибка видна без подмены выбранного режима |
| MS-04 | Подключённая совместимая модель другого семейства выбирается в той же панели и используется фактически, без изменения исходников для её названия |
| MS-05 | Discovered/unsupported/unavailable показывают причину; нет скрытой загрузки, inference, передачи в новый endpoint или замены моделью default |
| MS-06 | Кнопка моделей открывает только модельный выбор; кнопка параметров непосредственно справа открывает только настройки выполнения |
| MS-07 | Single/dual не сбрасывают коннектом/шаги/память; изменение параметров не меняет выбранные модели |
| MS-08 | Кнопка и панель состояния показывают реальные имена/роли, отключённый оценщик и фактические счётчики |
| MS-09 | Legacy request/history остаются читаемыми; explicit null отличается от missing; недоступная старая модель не подменяется |
| MS-10 | Допуск для другой модели/наличия оценщика/пары отклоняется до изменения окружения; benchmark и UI сохраняют одинаковую идентичность |
| MS-11 | Пока задача активна, обе кнопки заблокированы; snapshot/история не меняются от UI; открытие истории не переписывает личный default |
| MS-12 | На 320px/390px и desktop кнопки сохраняют порядок, области 44px, доступный Stop/Send, клавиатурное управление и отсутствие горизонтальной прокрутки |

## 8. Границы последующей реализации

Самостоятельная поставка на существующем одиночном агенте, без ожидания окончания
проектируемых фаз 15–25: nullable оценщик в shared cortex/config; единый каталог
совместимых моделей; две панели и соседние кнопки; сохранение/история; проверка
single/dual/generic model и области допуска. Детерминированные HTTP-стенды
подтверждают отсутствие Jev-запросов и выбор иных model IDs. Живой локальный
single-Qwen запуск и visual QA desktop/mobile подтверждаются отдельно.

Новые протоколы провайдеров, hot-swap модели в работающей попытке и автоматическая
загрузка весов не входят в это изменение. Они не нужны для последующего выбора
других совместимых моделей в существующем подключении LM Studio.
